Integration Decisions

This decision record incorporates the Burrow integration handoff. The five upstream changes were integrated in Hovel PRs #65–#69, followed by the build and report changes in #61. The reviewed combined source is 33eb385. Source integration, an official release containing that source, and downstream adoption are separate milestones. These changes were merged after the v0.4.3 release; installing v0.4.3 does not supply the four bug fixes.

Issue acceptance matrix

The matrix distinguishes implemented fixes, supported-contract clarification, and deliberate deferral. Each original Burrow issue retains its downstream obligations. A closed deferred request is not an implemented feature.

Issue and dispositionImplemented contract and evidenceRemaining boundary
#86: SQLite WAL locks
Fixed upstream in #65.		 The cached SQL pool owns the independent database/WAL/shared-memory security handles. Callers drain operations before close; the store closes the pool before its handles and serializes close/reopen. Initialization failure still cleans up. TestWALLifetimeLock probes the shared-memory lock from another process in the SQLite normal and race suites. See Workspace Database. The probe establishes lock preservation, not the cause of every historical daemon crash. Burrow still needs fixed-release adoption and concurrent-reader/write evidence.
#30: retained-session logs
Fixed upstream in #66.		 The newest 256 diagnostic entries remain ordered and bounded while live callback delivery continues. The resource-limit regression sends thousands of logs before and after Run returns, checks correlation and timestamps, and proves the retained owner still serves read/write/acknowledged close and closes its listener. Callback failure, byte limits, and credential suppression remain covered. See module/log. History eviction is not lossless in-memory retention or recovery from a failed event sink. Keep Burrow's diagnostic budget until its adopted runtime is verified.
#75: attached-shell catalogs
Fixed upstream in #67.		 The shell fetches the daemon catalog before replacing derived commands, counts, and wizard state. TestE2EAttachedModuleRefreshesLiveCatalog covers install/removal, fresh attachment, canceled refresh preserving an active wizard, and interactive refresh after another shell installs a module. See Attached catalog refresh. Existing refresh triggers remain the boundary; there is no polling, per-keystroke RPC, or new refresh command. This regression is in the explicit manual CLI E2E target.
#29: native terminal presentation
Restoration fixed upstream in #68.		 TestSessionConnectRestoresPresentation uses a Linux controlling PTY to cover detach, read failure, ordinary output, redirected output, and embedded-output isolation; it also checks termios, unchanged remote input, and session retention. See Session Control Plane. Native geometry, resize, controller fencing, and independent observers are separate deferred features. Burrow's provider-owned shared-shell commands do not imply native Hovel APIs.
#34: ordinary session commands
Existing contract clarified in #69.		 An ordinary retained Go session may implement PayloadCommandProvider without an installed-payload record. TestRetainedNonPayloadSessionCommandsStayWithOwnerAndEndOnClose verifies two concurrent correlated requests use the same owner and calls fail after close; the SDK round-trip test covers dispatch. See Retained-session commands. This was documentation and regression coverage, not a new runtime API. A command does not itself create a confirmed throw, generic durable completion event, or persisted output artifact.
#28: daemon compatibility negotiation
Deferred, not planned.		 Burrow's accepted baseline uses pinned local daemon instances with verified reuse. New running-build/protocol fields and client acceptance policy are not implemented by these changes. Revisit when arbitrary existing local/remote daemon attachment is explicitly required, or the accepted workflow cannot be supported safely. The maintainer must define compatibility policy; metadata is not authentication or attestation.
#39: automatic retained-result persistence
Deferred, not planned.		 Burrow's accepted lifecycle is prepare → confirmed launch → inspect/cancel → explicit collect → close, including possible loss of uncollected output on daemon/module failure. Revisit when unattended durable completion is an explicit unmet requirement. Define acknowledgment, failure/retry/restart behavior, and original-operation correlation using the existing evidence store before adding a lifecycle capability.

Build and report integration

PR #61 integrated declared lint actions shared by CI and reports, narrower MinGW inputs, aggregate deterministic wheel materialization, a pinned Wine runtime, and independent release rebuild verification. Each runner's cppcheck action now declares its own platform headers; FreeBSD and Windows must not silently analyze Linux copies. Temporary syntax errors in each platform's start header invalidated a prior passing result and failed at that header; restoring the files restored passing results. No probe changes were committed. See the Development Guide for source-list maintenance and report semantics.

Validation record and limits

The original submissions used baseline b4190bb (v0.4.3) and reported two SDK Mesh bridge timeouts that also reproduced on that baseline. Some manual CLI/broker targets additionally lacked external fixtures. Those historical results remain in the PRs; the integration did not weaken tests, timeouts, or CI policy.

During integration on 2026-09-27, each cumulative candidate passed the full aspect hovel-check, and all eight normal hosted PR jobs passed before merge. Focused SQLite normal/race, log-control, catalog-refresh, PTY, broker-command, and SDK round-trip tests also passed with test-result caching disabled. The final combined aspect hovel-report passed with all 14 linter entries green. These results supersede the earlier full-gate limitation for the tested integration environment; they do not claim that every historical manual-fixture problem is fixed.

The integration also observed a Mesh bridge race-test failure: its mock session-close notification can arrive before the bridge removes its registry entries. The hosted retry passed. The post-integration review reproduced the failure four times in 100 race-test iterations and corrected the test to wait for the natural-close critical section before asserting registry removal. This changes test synchronization only and is distinct from the terminal-restoration fix. Current generated evidence is available in the test report.

Downstream adoption remains separate

  • Adopt an official release containing the fixes through a separate Burrow runtime-pin/provenance change. A Hovel merge does not update the runtime Burrow ships.
  • For #86, verify concurrent public artifact reads and daemon writes, daemon survival, and post-shutdown integrity. Pass local and hosted gates before restoring SSH follow and all three hovel-followup diagnostics to required status.
  • For #30, retain Burrow's 200-diagnostic-message budget and suppression warning until the official fixed runtime is pinned and verified.
  • Recheck catalog, terminal, and session-command behavior against that adopted runtime before claiming Burrow compatibility.

Incorporating this handoff does not authorize deferred feature implementation or close Burrow's adoption tickets. Link the accepted documentation change back to #111 through the maintainer's normal handoff process.
