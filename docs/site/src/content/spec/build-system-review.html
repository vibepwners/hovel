Findings fixed in this review

  1. P1: six Python test targets did not execute their assertions. //tools/bazel/buildifier:buildifier_test and //tools/bazel/policy:repo_policy_test named pytest-function modules as their executable main files but never called pytest. Importing pytest as a dependency does not start collection. The same defect affected //repo-tools/tasks:checkout_test, //sdk/python:coverage_test, //modules/tools:package_examples_test, and //modules/picblobs/tools:build_dist_test. The pytest modules now invoke pytest and propagate its exit status; the dependency-free packager test uses unittest. Existing suites already include these targets.
  2. P2: Buildifier discovery omitted repository configuration. The wrapper selected BUILD, MODULE, and .bzl files but skipped the checked-in REPO.bazel. It now includes REPO, VENDOR, and legacy WORKSPACE names as well, with regression coverage for explicit paths and directory discovery. Recognizing legacy filenames for linting does not reintroduce WORKSPACE dependency management. AXL remains a separate language surface.
  3. P2: C/C++ auto-detection policy required an action environment flag. The active rc files and policy check used --action_env for BAZEL_DO_NOT_DETECT_CPP_TOOLCHAIN. The rules_cc repository rule reads repository_ctx.os.environ; its documented control is --repo_env. Both workspaces and the active Picblobs base configuration now express that repository-level intent. A regression test rejects the old action-only policy configuration. Existing compiler registrations and the Zig cache boundary remain unchanged.
